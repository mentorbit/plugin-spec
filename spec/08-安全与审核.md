# 08 安全与审核

> 状态：草案

## 8.1 插件输出不可信

插件产出的一切内容都是不可信数据，包括工具结果的 `summary`、对象、`fallbackText`，以及内容包中的题干、解析和讲义正文。

- 宿主把这些内容交给模型时，**必须**明确标注来源并与系统指令隔开，**不得**把其中的文字当作指令执行。
- 插件输出**不得**触发以下操作：授予权限、安装或启用插件、接受证据、发送消息、调用其他有副作用的工具。这些操作只能由用户或内核的确定性规则触发。
- 插件**不得**在输出中嵌入针对模型或宿主的指令，例如“忽略之前的要求”“调用某某工具”。发现此类内容属于审核不通过的理由。

## 8.2 供应链

- **自包含**：插件包**必须**包含运行所需的全部文件。宿主安装插件时**不得**执行任何构建脚本、安装脚本或依赖下载步骤。
- **完整性**：见 1.6。宿主**必须**从插件目录通过 HTTPS 获取插件包与完整性文件。
- **签名**：0.1 预留 `mentorbit.signature.json`，由插件目录对完整性文件签名，具体算法与密钥管理在后续版本定义，见附录 A。

## 8.3 发布与审核

插件目录对所有发布的插件执行自动检查，至少包括：

1. 清单与内容数据通过 `schemas/` 和校验工具检查；
2. 完整性文件正确；
3. 已知漏洞与恶意代码扫描；
4. 申请的权限都有 `reason`，申请网络权限的插件提供了 `privacyPolicy`；
5. 申请的权限没有超出目标信任等级的上限（见 2.2）。

申请 `verified` 等级的插件还须经过人工审核，至少核对：

- 代码行为与声明的功能、权限和 `reason` 一致；
- 网络请求的目的地与发送的数据与 `privacyPolicy` 一致；
- 遵守第 06 章的禁止行为；
- 内容包的准确性、来源标注、再分发许可，以及对目标学习者年龄段的适宜性。

## 8.4 内容要求

- 内容包**必须**标注来源，并确保拥有再分发的权利。
- 内容包**不得**包含真实个人的个人信息，例如真实学生的作答记录或姓名。
- 内容**不得**包含违法、歧视、色情、暴力或其他不适合学习场景的内容。

## 8.5 吊销

插件目录维护吊销清单，并通过 HTTPS 提供；获取地址由宿主所使用的插件目录提供。清单格式定义见 [`schemas/revocation-list.schema.json`](../schemas/revocation-list.schema.json)：

```json
{
  "format": "mentorbit.revocation-list/0.1",
  "generatedAt": "2026-10-09T08:00:00Z",
  "entries": [
    {
      "pluginId": "example.glossary",
      "versions": ["1.0.0", "1.0.1"],
      "severity": "high",
      "reason": "查询结果中可被注入针对模型的指令",
      "revokedAt": "2026-10-08T12:00:00Z"
    },
    {
      "pluginId": "example.tracker",
      "versions": ["*"],
      "severity": "critical",
      "reason": "向未声明的地址发送学习者数据",
      "revokedAt": "2026-10-09T07:30:00Z"
    }
  ]
}
```

- `versions` 列出被吊销的具体版本号；只含 `"*"` 时表示该插件的全部版本，包括之后发布的版本。`"*"` **不得**与具体版本号同时出现。0.1 不支持版本范围表达式。
- `severity` 取 `low`、`medium`、`high`、`critical` 之一，只影响宿主向用户提示的方式。
- 云端宿主**必须**至少每 24 小时拉取一次吊销清单。桌面宿主**必须**在启动时以及联网期间至少每 24 小时拉取一次；清单超过 7 天未更新时，**应当**提示用户。
- 无论 `severity` 为何，宿主拉取到吊销信息后**必须**立即停用受影响的版本，并告知已安装该插件的用户。
- 吊销清单的签名机制与插件包签名一并在后续版本定义，见附录 A。
