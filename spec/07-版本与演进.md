# 07 版本与演进

> 状态：草案

## 7.1 规范版本

- 规范自身使用 SemVer，当前为 `0.1.0-draft`。清单中的 `specVersion` 只写 `主.次`，例如 `"0.1"`。
- **1.0 之前**：每个次版本都可能包含不兼容变更。宿主**必须**声明自己支持哪些 `specVersion`，遇到不支持的版本**必须**拒绝加载并说明原因。
- **1.0 起**：次版本只做向后兼容的增加；不兼容变更只出现在主版本。支持 `X.Y` 的宿主**必须**接受所有 `X.y`（`y ≤ Y`）的清单。
- 运行协议标识与规范次版本绑定：渲染器协议为 `mentorbit.renderer/<主.次>`，工具协议为 `mentorbit.tool/<主.次>`。

## 7.2 插件版本

- 插件版本**必须**遵循 SemVer 2.0.0。同一插件 ID 的同一版本号一经发布**不得**更改内容，修正只能发布新版本。
- 宿主应当锁定已安装的版本，升级须由用户或部署方触发；升级涉及新增权限时，按 2.3 重新授权。

## 7.3 对象结构版本

- 对象类型的 `schemaVersion` 主版本变化表示不兼容。
- 宿主只把与渲染器所在插件当前声明的主版本一致的对象交给该渲染器；主版本不一致的旧对象，宿主**必须**改为展示其 `fallbackText`。

## 7.4 状态标签

规范中的每一章、每个扩展点和每个权限都带有以下状态之一。章节的状态标注在各章标题下方；扩展点的状态随其所在章节（内容包见第 03 章，渲染器见第 04 章，工具见第 05 章）；权限的状态见 2.2 的权限目录。

| 状态 | 含义 |
|---|---|
| 草案 | 1.0 之前的默认状态，可能变化 |
| 实验性 | 允许试用，任何版本都可能变化或移除；宿主**必须**由部署方显式启用后才提供 |
| 稳定 | 1.0 之后受兼容承诺保护 |
| 已废弃 | 仍然可用，但会在之后的主版本移除 |

1.0 起，标记为“已废弃”的功能至少保留两个次版本且不少于 6 个月，才能在下一个主版本中移除。

## 7.5 变更流程

1. **提案**：在仓库中提交议题，说明动机、方案、兼容性影响与备选方案。
2. **草稿**：提交修改。规范性变更**必须**在同一次修改中同步更新正文、`schemas/`、校验工具与受影响的示例；只改正文、没有对应校验的规则视为未生效。
3. **公示**：规范性变更合入前公示至少 14 天，期间收集意见。措辞修正、错别字等编辑性变更不需要公示。
4. **决定**：由维护者决定合入、修改或拒绝，并在 `CHANGELOG.md` 中记录变更与理由。

新增证据事件类型、新增学习者状态维度、新增扩展点都属于规范性变更。
