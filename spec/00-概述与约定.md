# 00 概述与约定

## 0.1 目的与范围

本规范定义 Mentorbit 插件与宿主之间的契约：插件如何打包和声明自己、可以向哪些扩展点贡献什么、运行时如何与宿主通信、能读取哪些数据、不得做什么，以及规范自身如何演进。

0.1 版覆盖三类贡献：**内容包**、**渲染器**、**工具**，以及它们共同依赖的清单、权限、对象、学习数据原则与安全要求。以下扩展点在 0.1 中**不开放**，相关名称保留：教学技能（skill）、轮次钩子（hook）、模型与搜索供应商（provider）、判题与执行器（judge）、岗位包（role package）。

## 0.2 设计原则

1. **内核固定，扩展有限。** 身份与归属、权限与审批、会话日志、学习者状态与证据归约、插件宿主本身属于内核，插件不能替换或绕过。
2. **默认拒绝。** 插件未声明并获授权的能力一律不可用；宿主在运行时强制执行，而不是依赖插件自觉。
3. **插件只能提议，不能裁决。** 插件可以产出内容、对象和证据提议；评分、掌握判定、长期记忆写入由内核的确定性规则决定。
4. **插件输出不可信。** 插件产出的文本和数据进入模型上下文或界面时，一律按不可信输入处理。
5. **语言无关。** 需要运行代码的插件通过本规范定义的协议与宿主通信，可以使用任何语言实现。

## 0.3 术语

| 术语 | 定义 |
|---|---|
| 宿主（Host） | 加载并运行插件、执行权限检查的 Mentorbit 程序，例如云端服务、桌面应用或离线演示环境 |
| 内核（Kernel） | 宿主中不可插拔的部分，见 0.2 第 1 条 |
| 插件（Plugin） | 由一个清单描述、以插件包形式分发的扩展单元 |
| 插件包（Package） | 包含清单及其引用文件的目录或归档 |
| 清单（Manifest） | 插件包根目录下的 `mentorbit.plugin.json`，见第 01 章 |
| 贡献（Contribution） | 插件在清单中向某个扩展点声明的一项内容，例如一个工具 |
| 扩展点（Extension point） | 内核开放给插件的接入位置 |
| 对象（Object） | 插件产出、带类型与版本的 JSON 数据，见第 05 章 |
| 发布者（Publisher） | 插件的作者身份，是插件 ID 的前半段 |
| 信任等级（Trust tier） | 宿主对插件的审核等级：`official`、`verified`、`community`，见第 02 章 |
| 学习者（Learner） | 使用宿主学习的人 |
| 学习者状态（Learner state） | 内核维护的学习者模型，按维度组织，见第 06 章 |
| 证据事件（Evidence event） | 内核登记过的、可以改变学习者状态的事件类型，见第 06 章 |

## 0.4 规范性用语

本规范使用下列用语表达要求强度，对应 RFC 2119 / RFC 8174：

| 本规范用语 | 含义 | 对应英文 |
|---|---|---|
| **必须** | 绝对要求 | MUST |
| **不得** | 绝对禁止 | MUST NOT |
| **应当** | 除非有充分理由并理解后果，否则须遵守 | SHOULD |
| **不应** | 除非有充分理由并理解后果，否则不得这样做 | SHOULD NOT |
| **可以** | 真正可选 | MAY |

只有加粗的上述用语具有规范效力。标注“说明”或“示例”的段落不具规范效力。

## 0.5 合规对象

本规范对两类实现提出要求：

- **合规插件**：清单与数据通过 `schemas/` 校验，并满足各章中针对插件的全部“必须/不得”要求。
- **合规宿主**：实现本规范中针对宿主的全部“必须/不得”要求，并对插件强制执行权限与安全规则。

宿主**可以**只实现部分扩展点；未实现的扩展点下的贡献，宿主**必须**忽略并向用户说明，**不得**因此拒绝加载整个插件，除非该贡献在清单中标记为必需（见 1.4）。

## 0.6 标识符约定

- 插件 ID：`<发布者>.<名称>`，例如 `example.intro-cs`。规则见 1.3。
- 贡献 ID：在同一插件内唯一，匹配 `^[a-z][a-z0-9_]{1,31}$`。
- 全局限定名：`<插件 ID>/<贡献 ID>`，例如 `example.glossary/lookup_term`。宿主在跨插件场景中**必须**使用全局限定名。
- 时间：RFC 3339 格式的 UTC 时间字符串。
- 文本：UTF-8 编码。
