# 02 权限与信任

## 2.1 基本规则

- 插件只能使用已在清单中申请、且已获授权的权限。宿主**必须**在运行时强制执行，不得依赖插件自律。
- 未申请任何权限的插件仍可：读取自己包内的文件、接收工具调用参数与不透明的作用域引用、渲染自己声明的对象类型、产出对象。
- 宿主**必须**对所有插件采用默认拒绝。

## 2.2 权限目录

| 权限 ID | 含义 | 最低信任等级 |
|---|---|---|
| `storage.plugin` | 读写该插件私有的键值存储。存储按“插件 × 学习者”隔离，宿主应当至少提供 5 MiB 配额 | `community` |
| `model.invoke` | 通过宿主调用大语言模型。插件拿不到模型凭据，调用计入宿主设定的配额 | `community` |
| `network:<origin>` | 通过宿主代理访问指定 HTTPS 源，`<origin>` 为 `https://主机[:端口]`，不得含通配符、路径或查询串。每个插件最多申请 5 个 | `community` |
| `objects.read:<插件 ID>/<对象类型>` | 读取当前会话中由其他插件产出的指定类型对象 | `verified` |
| `context.read:message` | 在工具被调用时读取学习者当前这条消息的原文，而不仅是模型给出的参数 | `verified` |
| `learner.read:<维度>` | 读取学习者状态某一维度的受限投影，维度见第 06 章；`human` 维度除外 | `verified` |
| `learner.read:human` | 读取 `human` 维度投影（偏好、节奏、负荷等敏感信息） | `official` |
| `evidence.propose:<事件类型>` | 提议内核已登记的证据事件，见第 06 章（实验性） | `official` |

宿主**必须**拒绝加载申请了超出其信任等级权限的插件，**不得**静默降级授权。

清单中每项权限的写法：

```json
{ "id": "network:https://api.example.com", "reason": "查询公开术语词典", "optional": true }
```

- `reason` 必需，不超过 120 个字符，会原样展示给授权人。
- `optional` 默认为 `false`。可选权限被拒绝时插件**必须**仍能工作；必需权限被拒绝时宿主**不得**启用该插件。

## 2.3 授权流程

1. **安装时**：宿主**必须**向授权人逐项展示申请的权限、`reason` 和插件信任等级，取得明确同意后才能启用。授权人由部署策略决定，可以是学习者本人、监护人或机构管理员；面向未成年学习者的部署应当由监护人或机构参与授权。
2. **升级时**：新版本申请了旧版本没有的权限，或扩大了已有权限的范围（例如新增网络源）时，宿主**必须**重新取得同意；在取得同意前，宿主**必须**继续运行旧版本或停用该插件，**不得**自动以新权限运行。
3. **撤销**：授权人**必须**能随时撤销任一权限或停用插件。撤销后插件再请求相应能力时，宿主返回 `permission_denied` 错误（见第 05 章），插件**必须**妥善处理而不是崩溃。
4. **卸载**：宿主**必须**删除该插件的私有存储，并按第 06 章处理插件产出的对象。

## 2.4 宿主强制执行要求

- **网络**：插件代码**不得**直接访问网络。宿主**必须**为工具进程隔离网络，只通过宿主代理放行已授权的源；渲染器的网络限制见第 04 章。
- **文件系统**：工具进程只能读取自己的包目录和宿主提供的临时目录，**不得**访问宿主数据、其他插件或用户文件。
- **资源**：宿主**必须**对每个工具进程限制 CPU 时间、内存与并发调用数，超限时终止进程并向调用方返回 `resource_exhausted`。
- **无法保证的隔离**：如果某种运行环境（例如桌面端的本地开发模式）无法提供上述隔离，宿主**必须**在界面上持续标示“未受管”，**不得**宣称其已隔离。

## 2.5 信任等级

| 等级 | 获得方式 |
|---|---|
| `official` | 由 Mentorbit 维护者发布 |
| `verified` | 经插件目录人工审核，发布者身份已验证，见第 08 章 |
| `community` | 已在插件目录发布并通过自动检查，未经人工审核 |
| `local` | 未经插件目录发布，例如开发者从本地目录加载 |

信任等级由插件目录和宿主判定，插件**不得**在清单中自报。

不同运行环境的要求：

- **云端宿主**（多个学习者共享的服务）**不得**运行 `local` 插件；运行 `community` 插件前应当经过部署方的启用审批。
- **桌面宿主**（运行在学习者本人设备上）**可以**运行 `local` 插件，但**必须**事先取得用户明确同意，并持续标示其未经审核。
- 无论信任等级，本规范定义的工具一律以隔离进程运行（见第 05 章），渲染器一律在沙箱 iframe 中运行（见第 04 章）。信任等级只决定可申请的权限上限，不放宽隔离。
